One Linux account, isolation per SSH key. Each developer's key starts the session through a small server-side launcher that fixes the e-mail (the line lives in root-owned authorized_keys, so it cannot be spoofed), and the whole session then runs inside a kernel mount namespace that contains only the applications granted to that e-mail on the Permissions page. How the isolation works (and its honest limits)

The launcher is a forced command on each key; the e-mail is read from the key line, never from the client. The session is a bubblewrap namespace: system binaries are read-only, the home is a per-developer workspace, and each granted app is bind-mounted into it. Nothing else exists in that namespace — this is kernel enforcement, not a shell wrapper that could be bypassed with another command.

Limit: a developer can read the source of every application you grant them (that is what developing means), but nothing beyond that list. Disable password SSH logins on the server (key-only auth), otherwise the shared account password would bypass the per-key launcher.

How to register a new developer

On the server, add their public key to the authority file:

echo "ssh-ed25519 AAAA... dev.name@company.com" >> ~/.ssh/authorized_keys

The e-mail must be part of the key comment (or an environment="GIT_AUTHOR_EMAIL=..." option). Then press Sync users from authorized_keys above — the user appears here automatically and every hook is refreshed.

How does the developer create a key?

Each developer generates their key pair on their own machine and sends only the public half (.pub) to be pasted above. The private key never leaves their computer.

💻 Windows (PowerShell) 
ssh-keygen -t ed25519 -C "name@company.com"
# press Enter twice (empty passphrase is enough for identifing),
# stored at:  C:\Users\<user>\.ssh\id_ed25519.pub

# copy the PUBLIC key to the clipboard:
type $env:USERPROFILE\.ssh\id_ed25519.pub | clip

# or show it in the terminal to copy by mouse:
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
🐦 Linux 
ssh-keygen -t ed25519 -C "name@company.com"
# stored at:  ~/.ssh/id_ed25519.pub

# show it (copy the whole line):
cat ~/.ssh/id_ed25519.pub

# or copy it straight to the clipboard (if xclip is installed):
xclip -selection clipboard < ~/.ssh/id_ed25519.pub
🍌 macOS 
ssh-keygen -t ed25519 -C "name@company.com"
# stored at:  ~/.ssh/id_ed25519.pub

# copy the PUBLIC key to the clipboard instantly:
pbcopy < ~/.ssh/id_ed25519.pub

# or display it:
cat ~/.ssh/id_ed25519.pub

The -C "email" part is important — it is what Git Gateway reads to know whose key it is and stamp commits with their identity. After pasting the key here, the developer connects with ssh user@server and starts working on the applications.
